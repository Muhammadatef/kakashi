kakashi

hide what shouldn't leave your machine

A local-first privacy engine for agentic AI. It finds secrets and personal data in your files, folders and databases, and it can decide by itself how much of that data an agent may have for the job the agent says it's doing.

The problem

Every day, on every dev team, someone does this:

# "Let me just ask Claude why this query is failing..."
cat quarterly_report.xlsx | claude

# "Cursor, fix the auth bug in this file"
# (the file contains the production DB password)

Those files hold things that should never leave your machine: database connection strings, API keys, GitHub tokens, emails, phone numbers, card numbers, national IDs. There's no warning and no friction. They end up on a third-party server in plaintext, and you can't take them back.

The newer problem: agents now move data without asking first. They read files, query databases and call tools by themselves. "Remember to mask it" doesn't work as a control when nobody is at the keyboard.

Kakashi sits between the file on your disk and the model on someone else's server. It runs completely on your machine: no daemon, no cloud, no telemetry.

How it works: four layers

You can use each layer on its own, or let /kakashi pick the right one based on what you ask for.

Layer 1 · Engine

Find & mask

35 patterns (credentials, government IDs, financial, contact, names) across 50+ formats. Rebuilds the original file, so a .docx comes back as a real .docx.

scan mask audit

Layer 2 · Reach

Folders & databases

Whole repos and shared drives get a PDPL-mapped compliance report. Live databases are queried and masked on your machine.

scan-dir mask-dir db-scan db-mask

Layer 3 · Guardian

Autonomous guardrails

Takes a file, an agent and a task. It assesses the risk, plans the minimum necessary protection, checks its own output again, and returns a decision.

guard agent-guard

Layer 4 · Sweep

Where does customer data go?

Repo-wide data-flow audit over SQL, dbt, Python, notebooks and Airflow. Kakashi runs the process and the LLM only judges. Workers never see raw PII.

sweep

The Guardian loop

GOAL   protect sensitive information while preserving task utility
  ├─ OBSERVE          what is in this resource?        → 9 sensitivity classes
  ├─ UNDERSTAND TASK  what does the agent need it for?  → per-class requirement
  ├─ ASSESS           how risky is this release?         → 0–100, every factor named
  ├─ PLAN             minimum necessary transform per class
  ├─ POLICY           deterministic veto, so a rejected plan never runs
  ├─ EXECUTE          write the protected artifact
  ├─ VERIFY           re-scan its own output
  └─ REPLAN           still unsafe? strengthen and loop (budget: 4)
       ▼
  ALLOW · ALLOW_WITH_TRANSFORMATION · REQUIRE_APPROVAL · BLOCK
The task can only add protection. The task string comes from the agent Kakashi is protecting data from, so Kakashi treats it as hostile input. No stated purpose can unlock plaintext, and leaving the purpose out adds risk points. A property test checks this across all 504 intent × class × tool combinations.

Demos

Watch the walkthrough, then run the same six demos on your own machine. They generate synthetic data and run fully offline.

A real Guardian run

$ kakashi guard employees.md --agent claude \
    --task "calculate average salary by age group" --destination external_model

OBSERVE      21 finding(s) across 6 data class(es)
ASSESS       Risk: 95/100 — CRITICAL
PLAN         CONTACT, FINANCIAL, GOV_ID, PERSON_NAME → stable tokens
             LOCATION, QUASI_IDENTIFIER          → preserved (task needs them)
VERIFY       PASS — 0 prohibited class(es) remain
DECISION     ALLOW WITH TRANSFORMATION

Age bands and location are kept because the task can't be done without them. Salaries are tokenised consistently, so "group by" still works. The agent gets a file it can do the job with, and nothing beyond that.

$ kakashi guard service.env --agent unknown --destination external_model
ASSESS       Risk: 100/100 — CRITICAL
DECISION     REQUIRE HUMAN APPROVAL — awaiting approval for: CREDENTIAL
             No artifact was written.

When it's unsure, it fails closed: nothing is written, and the output says why.

How to use it

  1. Install (~30 s). It finds every AI agent on your machine and installs for all of them. Requires Node ≥ 18. 
    curl -fsSL https://raw.githubusercontent.com/Muhammadatef/kakashi/main/install.sh | bash
# preview first:   ... | bash -s -- --dry-run
# one agent only:  ... | bash -s -- --only cursor
    irm https://raw.githubusercontent.com/Muhammadatef/kakashi/main/install.ps1 | iex
    npm install -g @muhammadatef/kakashi
# or straight from GitHub
npx -y github:Muhammadatef/kakashi
  2. Protect a file 
    kakashi scan config/settings.py     # counts only, safe for agents to read
kakashi mask config/settings.py     # → masked_settings.py
kakashi mask file.env --mode redact # typed (default) | redact | fake
  3. Audit a folder 
    kakashi scan-dir ./repo -f html -o compliance.html          # PDPL-mapped report
kakashi scan-dir ./repo -f html -o compliance.html --lang ar  # Arabic
kakashi mask-dir ./deliverables -r --ext xlsx,docx,csv
  4. Mask a database (Postgres, MySQL, MongoDB, Snowflake, Databricks, SQLite) 
    kakashi db-scan "postgres://user:pass@host/db" -q "SELECT * FROM customers"
kakashi db-mask "postgres://user:pass@host/db" -q "SELECT * FROM customers" -f csv -o safe.csv
  5. Let the Guardian decide 
    kakashi guard employees.md --agent claude \
  --task "calculate average salary by age group" --destination external_model
kakashi guard data.csv --agent cursor --task "..." --json   # for agents: classes & counts only
  6. Audit data flow across a repo 
    kakashi sweep . --task "audit where customer data goes" --agent claude --destination external_model
kakashi sweep next && kakashi sweep submit <batch_id> findings.json
kakashi sweep reduce && kakashi sweep report -f md -o kakashi-sweep.md
  7. Or just ask your agent. In Claude, Cursor, Codex, Windsurf, Copilot and others: 
    /kakashi check this file
use kakashi to scan this repository
kakashi can I send this report to Claude for a summary?
Inside an agent, pass a path, not an @-mention. /kakashi-scan /path/to/file.env keeps the file off the wire. An @file.env mention makes the agent attach the whole file to the model before Kakashi runs. scan, db-scan and guard --json are safe for agents to read. audit, db-audit and --include-values show plaintext on purpose.

Command reference

CommandWhat it does
scan <file>Report counts only and write nothing (agent-safe)
mask <file>Mask and rebuild the original format
audit <file>Full original → token map (shows secrets)
scan-dir / mask-dirRecursive report / batch mask
db-scan / db-mask / db-auditThe same for database query results
guard <file>Autonomous release decision
agent-guardLocal loopback privacy sidecar
sweepRepo data-flow audit → PII source → sink chains
stats · impact · list-patternsCounters, value-free snapshot, all 35 patterns

Global flags: --mode typed|redact|fake, --whitelist, --output, --stdin, --lang en|ar. Alias: k.
